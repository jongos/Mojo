# Product Copy

Make the product understandable before making it sound impressive. Organize longer copy around the reader's purpose, supported capabilities, practical benefits, and a usable next step. This is an information hierarchy, not a mandatory page template.

Separate a capability from an outcome: grouping invoices by supplier is a capability; halving bookkeeping time is a measured outcome only when supporting evidence exists. Mechanisms can explain value without invented metrics: “Compare supplier totals in one view.”

Use “AI” when it explains something meaningful about the product, its data use, or expected behavior. Do not repeat it as a substitute for describing the feature.

Put material conditions beside the claim or action they qualify. A paid export belongs beside the export offer; external processing belongs where the user chooses to upload. Keep required disclosures intact. Do not bury conditions in methodology pages or footnotes merely to make an overview cleaner.

Use actual supporting documentation for methodology, provenance, maintenance, and technical detail. If no suitable reference exists, omit optional detail or retain what is necessary; do not invent a destination or create documentation without task authorization.

Do not label every page a draft or experiment. An approval-dependent document or unavailable feature may need a precise status; an ordinary overview usually does not. Respect genuine product labels and user-requested wording.

Actions should say what happens: “Download the report,” “Review changes,” or “Create an account.” Only offer actions and recovery paths that exist. Preserve accessibility, consistency, and established product terminology.
